
# Building a Network Intrusion Detection and Monitoring Lab with Snort and Wazuh

## Project Overview

**Objective:** Build a controlled virtual lab to generate network traffic, detect selected activity using a custom Snort rule, and forward the resulting alerts to Wazuh for centralized monitoring.

**Tools and Technologies:** VirtualBox, Kali Linux, Ubuntu 24.04 LTS, Nmap, Snort, Wazuh, Wireshark, Docker Compose

**Lab Environment:**

* **Kali Linux:** `192.168.56.104` — source of test traffic


* **Ubuntu 24.04 LTS:** `192.168.56.107` — Snort IDS and Wazuh agent


* **Network:** VirtualBox Host-Only network (`enp0s8`)


* **SIEM:** Wazuh manager, indexer, and dashboard deployed using Docker Compose



---

## 1. Project Objective and Architecture

I built an isolated attack-and-defend lab to explore how network activity can be detected and how the resulting security events can be collected centrally for investigation.

The lab consisted of two virtual machines connected through an isolated VirtualBox Host-Only network (`enp0s8`). Kali Linux was used to generate test traffic, while Ubuntu hosted Snort, the Network Intrusion Detection System (NIDS), and the Wazuh agent.

The Wazuh manager, indexer, and dashboard ran in Docker on the Ubuntu host. The Wazuh agent collected local Snort alerts and forwarded the events to the manager for centralized visibility.

The objective was to establish and validate the following workflow:

1. Generate controlled network traffic from Kali Linux.


2. Inspect the traffic using Wireshark.


3. Configure a custom Snort rule to detect matching TCP SYN packets.


4. Verify that Snort generates the expected alerts.


5. Configure the Wazuh agent to monitor Snort's alert log.


6. Confirm that the resulting events appear in the Wazuh dashboard.



This setup provided a practical way to examine the relationship between network-level detection and centralized security monitoring.

## 3. Configuring Snort and Developing a Custom Detection Rule

I configured Snort to inspect traffic on Ubuntu's Host-Only network interface, `enp0s8`, which connected Ubuntu to the isolated lab network.

I authored a custom rule in `/etc/snort/rules/local.rules`:

```snort
alert tcp 192.168.56.104 any -> 192.168.56.107 any (msg:"LAB Nmap SYN probe from Kali"; flags:S; flow:stateless; sid:1000001; rev:1;)

```

The rule was designed to generate an alert whenever a TCP packet sent from Kali to Ubuntu matched the specified SYN-flag condition.

The key components were:

* `alert tcp` — generate an alert for matching TCP traffic.


* `192.168.56.104 any` — match the source IP of the Kali VM, regardless of source port.


* `-> 192.168.56.107 any` — match traffic directed to the Ubuntu target IP, regardless of destination port.


* `flags:S` — match packets with the TCP SYN flag set.


* `flow:stateless` — evaluate packets individually without requiring an established TCP session.


* `sid:1000001` — assign a unique Snort signature ID to the custom rule.


* `rev:1` — track the rule revision number.

## 4. Integrating Snort Alerts with Wazuh SIEM

After verifying that Snort generated alerts locally, I configured Wazuh to collect the events for centralized monitoring.

The Wazuh agent (`wazuh-agent`) was installed on Ubuntu and configured to point to the manager at `127.0.0.1`.

```bash
wget https://packages.wazuh.com/4.x/apt/pool/main/w/wazuh-agent/wazuh-agent_4.7.5-1_amd64.deb
sudo WAZUH_MANAGER='127.0.0.1' WAZUH_AGENT_NAME='Ubuntu-Target' dpkg -i ./wazuh-agent_4.7.5-1_amd64.deb
sudo systemctl daemon-reload
sudo systemctl enable --now wazuh-agent

```

To ingest the Snort alerts into Wazuh, the local log collection section was defined inside `/var/ossec/etc/ossec.conf`:

```xml
<localfile>
  <log_format>snort-fast</log_format>
  <location>/var/log/snort/snort.alert.fast</location>
</localfile>

```

The `snort-fast` setting instructs Wazuh to parse the standard Snort fast-alert log format from `/var/log/snort/snort.alert.fast`.

After restarting the agent service, I generated another Nmap scan from Kali to verify event ingestion on the SIEM dashboard (`https://localhost`).

The events appeared in Wazuh under the description `IDS event.` and were mapped to **Rule ID 20101** (Level 6).

## 5. Results and Technical Findings

The lab successfully demonstrated an operational network detection and centralized monitoring pipeline.

Key outcomes verified:

* **Traffic Generation:** Nmap successfully delivered TCP SYN probes from Kali Linux to Ubuntu.


* **Packet Inspection:** Wireshark captured and verified packet headers between the hosts.


* **Custom Detection:** Snort flagged packets matching SID `1000001` and wrote alerts to log files.


* **Log Aggregation:** The Wazuh agent monitored `/var/log/snort/snort.alert.fast` and forwarded logs to the manager.


* **Centralized Visibility:** Corresponding events surfaced in real time on the Wazuh dashboard.


* **Event Investigation:** The dashboard exposed source IP addresses, destination ports, raw alert text, and decoder metadata.



Tracing an event across each layer—from packet generation through local signature matching to SIEM parsing—highlighted the mechanics of modern SOC detection engineering.

---

## 6. Limitations and Potential Improvements

This implementation establishes a foundational detection workflow. Future lab iterations could incorporate the following extensions:

* **Refine Signature Logic:** Expand Snort rules to differentiate single connection attempts from high-volume port sweeps.


* **Custom Wazuh Rules:** Write tailored Wazuh XML rules to elevate specific Snort SID alerts to higher severity levels or trigger active responses.


* **Automated Active Response:** Configure Wazuh to trigger active response scripts (such as dynamically dropping offending IPs via UFW) upon detecting repeated scanning activity.
* **Protocol Expansion:** Test additional attack vectors, including SSH brute-force attempts and web application attacks, to evaluate multi-decoder capabilities.

---

## Conclusion

This project provided practical experience in building, configuring, and validating an integrated network intrusion detection and security monitoring environment.

Using Nmap for traffic generation, Wireshark for packet analysis, Snort for signature development, and Wazuh for centralized log visualization, the lab demonstrated how offensive probes are detected and translated into actionable defensive intelligence.
